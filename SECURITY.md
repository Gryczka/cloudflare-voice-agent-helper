# Security Policy

## Supported Versions

This is a reference/demo repository shared as-is (see
[SUPPORT.md](SUPPORT.md)). There are no versioned releases — security fixes,
if any, land on `main` only.

| Branch | Supported |
| ------ | --------- |
| `main` | ✅        |

## Reporting a Vulnerability

This project is a reference sample and is not actively maintained, so
please report suspected vulnerabilities via
[GitHub Issues](../../issues) rather than a private security contact.

When filing, please:

- Avoid including live exploit details or working proof-of-concept code
  in the public issue body if the report is sensitive; a high-level
  description is enough for a first pass.
- Include the affected file(s)/component and, if possible, a minimal
  reproduction.

## Response Timeline

Because this is a best-effort reference repository, there is no guaranteed
response time. We'll do our best to acknowledge reports and, for anything
that looks like a real issue, follow up with a fix or mitigation guidance.

## Disclosure Policy

Given the "use GitHub Issues" reporting model above, disclosure is
effectively public at the time of reporting. If you believe a finding is
severe enough to warrant coordinated, non-public disclosure, please say so
explicitly in the issue title (e.g. "[Sensitive] ...") and keep exploit
details out of the initial report; a maintainer will follow up on how to
share further detail.
